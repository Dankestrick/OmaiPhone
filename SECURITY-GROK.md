# OmaiPhone security notes (sec/grok)

The phone, or a device pretending to be it, is the untrusted input. These notes cover parsing, storage, and actions on bytes that come from that device: `backend/texts/` (MAP, PBAP, the message store) and the matching modules under `backend/omaiphone/`. Pairing, device identity, `bluez.py`, `daemon.py`, `control.py`, `cli.py`, the IPC surface, and `qml/` were left for the other checkout.

`companion.py` is outside that file list. The ANCS cap has to live there because that is where notification bytes and uid maps accumulate. It is included below for that reason.

Line numbers are on `sec/grok` after these commits.

| Location | Severity | What a malicious phone could do | Status |
| --- | --- | --- | --- |
| `backend/texts/bluetooth.py:109` | high | MAP message handles are phone-supplied. A handle such as `../../../../../../tmp/pwn` was joined onto the runtime directory, so obexd wrote that path and the session unlinked it. A symlink at the target would have been followed. | Fixed in `ceeb244`. Handles must match `^[0-9A-Fa-f]{1,16}$`. The download file is created with `O_NOFOLLOW` and mode 0600. Reads stop at 128 KiB. The handle and failure maps stop at 500 entries. A bad handle counts as a failed download and is given up after 3 tries. |
| `backend/texts/store.py:38`, `store.py:166`, `store.py:252` | med | Message ids, bodies, addresses, timestamps, and the contact list were clipped on the way out and not on the way in, so one phone could grow the database without a bound. | Fixed in `5ae46a0`. Ids longer than 128 bytes become a hash. Bodies, addresses, and timestamps are clipped. Direction is only `in` or `out`. Contacts stop at 5000. Messages prune to 2000 oldest-first. |
| `backend/texts/protocol.py:236`, `protocol.py:273` | med | A downloaded bMessage already in memory was scanned, including a large base64 attachment, with no length cap. | Fixed in `5ae46a0`. The scan and the text kept from it are limited. |
| `backend/texts/messagesd.py:43`, `messagesd.py:64`, `messagesd.py:107` | high | `notify-send` is started without a shell, but GLib's option parser treats a title that starts with `-` as an option unless `--` comes first. The notification body is markup (`<img>`, `<a href>`). A burst of texts started one process per message. | Fixed in `24549fa`. Titles and bodies are truncated, NUL-stripped, and escaped, and `--` is passed before the title. At most two `notify-send` processes run; each is killed after 5 seconds. |
| `backend/texts/protocol.py:359` | med | The overlay's error fallback showed the exception text. A failure string can contain a phone number, a path, or `BEGIN:MSG` body text. | Fixed in `24549fa`. The fallback is a generic sentence unless the text is short and has fewer than six digits and no `@`, `/`, `<`, `>`, or `BEGIN:`. Known Bluetooth failures still map to our own sentences. |
| `backend/omaiphone/ancs.py:97` | high | An ANCS attribute length is a uint16 (up to 65535). The parser waited until that many bytes arrived, so a declared length with no following bytes was buffered until the command timed out. A command byte that never matched kept the buffer growing for the same window. | Fixed in `609ad15`. A length over 512 bytes, or an app id over 128 bytes, raises immediately, before those bytes arrive. NUL bytes inside a value are stripped. Media text is clipped to 200 characters. |
| `backend/omaiphone/companion.py:201`, `companion.py:216` | med | The same ANCS stream appended into `_data` with no cap, and every notification uid and app name was kept. | Fixed in `609ad15`, in `companion.py` because that is the accumulator. `_data` keeps the last 4096 bytes. Uid and app-name maps stop at 400; the oldest uid is dropped and its attribute command is cancelled. |
| `backend/omaiphone/notifications.py:13`, `notifications.py:30`, `notifications.py:115`; `mirror.py:20` | med | The mirrored notification list grew with every phone event. Toast title and body were handed to the notification daemon as markup. Phone error text was written to the log in full. | Fixed in `71120cd`. The list keeps 60 items and records evicted uids so those toasts are closed. Fields are clipped to 500 characters. `toast_payload` escapes markup. Log lines are one 180-character line. |
| `backend/omaiphone/att.py:147` | high | Service, characteristic, and descriptor discovery asked for the next handle after the phone's end handle. An end handle that did not move forward (for example 0 while the start was 1) requested the same range forever. | Fixed in `69f07b3`. If the next start is not greater than the current start, or the cursor is outside 0..0xFFFE, discovery stops with an error. A range that reaches 0xFFFF still completes. |
| `backend/omaiphone/contacts.py:218`, `contacts.py:58`, `contacts.py:372`; `backend/texts/protocol.py:298`; `backend/texts/bluetooth.py:892` | high | A PBAP download was read with no size limit. The path obexd reported was opened and deleted as given, including a path outside the temp directory, and a symlink would have been followed. vCard names, numbers, and the call log were unbounded. The shared `contacts.json` was read in full. | Fixed in `e397b35`. The file is read only when its real parent is the temp directory, with `O_NOFOLLOW`, and at most 2 MiB. Cards stop at 5000, history at 500 newest, and each name and number is clipped. `record_call` ignores a kind other than missed, received, or dialed. bMessage vCards keep 8 cards and 8 values. `contacts.json` over 2 MiB, or not a dict of lists, is refused. |
| `backend/omaiphone/events.py:20`, `events.py:56`; `state.py:50`; `telephony.py:75` | med | Caller name, number, call state, and Bluetooth address were stored and shown as the phone (via PipeWire properties) sent them. `codec_name` called `int()` on the codec id and, for an unknown id, put that value in the codec label. `from_pipewire` put the raw state in the `ValueError`, which the daemon logs. | Fixed in `be49002`. Name and number are one 80-character line; state and address are 32. A missing caller-id property stays `None`. Codec ids must be an integer 0..255, and a digit string longer than 8 characters is rejected; 0 still has an empty name. The PipeWire error text is `unknown call state` and does not repeat the value. The same clips apply when calls are read at startup through `Telephony.calls`. Volume levels that are not a byte are dropped. |
| `backend/omaiphone/gatt.py:171`; `att.py:129`, `att.py:244`; `rawatt.py:20` | med | BlueZ reassembles a GATT value and can deliver more than one ATT packet. That value was copied into the notification callback. On the raw socket, one GLib wake called `recv` until the socket was quiet, so a phone that kept the socket readable stalled the main loop. | Fixed in `8f414b4`. Values over 4096 bytes are dropped before the second copy, including ATT notifications (an indication is still confirmed). One wake reads at most 32 packets and returns so the watch can run again. |
| `backend/texts/bluetooth.py:81`, `bluetooth.py:118`, `bluetooth.py:178` | med | A MAP `Handle` is phone-supplied. Handles must be hex of at most 16 digits. Listings and the live-message pass stop at 40. Timestamps use the first 32 characters. Object paths longer than 240 characters are not kept. | `backend/texts/store.py:50`, `store.py:55` | med | An id or body over the cap was still copied and hashed in full, so a multi-megabyte field cost that much before it was discarded. | `backend/omaiphone/companion.py:70`, `companion.py:328` | med | If the phone sends notification text and never the app name, every later notification for that app stayed on `_waiting`, and each new app id queued another command with no cap. | Fixed in `04d0c8f`. Removing a uid drops it from the wait lists. |

The mirror `Toaster` in `mirror.py` and the `notify-send` call in `backend/texts/messagesd.py` are already escaped on this branch (`71120cd`, `24549fa`) and again on `sec/claude`. They were not edited further.

## Left open

| Location | Severity | What a malicious phone could do | Why it is still open |
| --- | --- | --- | --- |
| `backend/omaiphone/daemon.py:339` | med | The incoming-call notification body is the caller name and number, unescaped. Freedesktop notification bodies are markup, so a name of `<img src="...">` or `<a href="...">` is rendered by the notification daemon. `be49002` limits each field to 80 characters on the way into the daemon, which bounds the payload and does not escape it. | `daemon.py` is the other checkout's file. Escaping belongs at this Notify call. |
| `backend/omaiphone/daemon.py:100` | low | At startup the Bluetooth address is copied off the gateway properties without the clip in `events.clip_text`. A live connect event is clipped. An enormous address string would be stored and later written into the audio state file. PipeWire normally puts a BD_ADDR here; this is only a problem if that property is not a short address. | The read is in `daemon.py`. |
| `backend/omaiphone/daemon.py:230` | low | An unknown call state is logged with `value`. After `be49002` that value is already one 32-character line, so the log cannot grow with the phone's string. The line can still contain those 32 characters. | Logging is in `daemon.py`. The exception from `from_pipewire` no longer includes the raw text. |
| `backend/omaiphone/state.py:76` | low | `CallStateMachine.history` grows by one entry every time the phone moves the call, including active/held forever. | `daemon.py` `_record` decides missed, received, or dialed by whether `INCOMING`, `ACTIVE`, `DIALING`, or `ALERTING` appear in that list. Dropping early entries would record the call as the wrong kind. One call's list of short enum values is a small leak, not a parser bug. |
| `backend/texts/store.py:85` | low | `sqlite3.connect` creates `messages.db` with the process umask (often 0644) and `_ensure_mode` chmods it to 0600 just after. The parent directory is 0700, so other users cannot walk in during that window. | The window is inside a private directory. Chmod-on-every-write was avoided on purpose: a chmod under `~/.local/share` makes the shell rescan plugins. |

## Suspected, not confirmed

- MAP folder listings are XML parsed by obexd, not by this code. There is no XML parser here, so a billion-laughs payload would land in obexd. The normal listing request asks for `MaxCount` 40 and `SubjectLength` 255 (`bluetooth.py:677`). The fallback at `bluetooth.py:682` omits those limits. Whatever obexd returns is still clipped before it is stored (`5ae46a0`). obexd itself was not audited.
- obexd's PBAP client writes the phone book with `g_file_open_tmp` (`obex-clientXXXXXX` under `TMPDIR`). The phone does not choose that local path. The checks in `e397b35` refuse a path that is not in the temp directory in case that changes.
- Quote-printable `PHOTO` lines in a vCard are not decoded. `contacts.py` unfolds continuation lines and then applies the 2 MiB and per-field caps. `protocol.parse_vcards` skips folded continuation lines rather than unfolding them. A photo cannot expand past the byte cap we already enforce.
- `gatt.py` `discover_services` keeps BlueZ's whole `GetManagedObjects` tree. How large that is depends on bluetoothd. This process does not add its own cap on the number of services.
- `mirror.py` reconnects with a backoff that levels off at 300 seconds, and asks for notification permission again every 30 seconds. Those loops are intentional. Message downloads already stop after 3 failures.
- `public_error` still shows a short exception string when it looks harmless (for example "adapter is off"). A short phrase with fewer than six digits and none of the rejected characters can still reach the overlay.
